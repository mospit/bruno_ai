1. Overview of Instacart APIs

Instacart offers multiple API platforms to integrate shopping, delivery, and advertising capabilities into third-party applications and websites. The APIs are designed to provide comprehensive e-commerce functionality while maintaining security and scalability.

1.1 API Platforms

Developer Platform API

The Developer Platform API enables developers to create shoppable recipes, shopping lists, and integrate basic shopping experiences. It uses API key authentication and is designed for simpler integrations.

Connect APIs

Connect APIs provide comprehensive e-commerce functionality for branded retailer sites, including fulfillment, recommendations, and customer management. These APIs use OAuth 2.0 authentication and offer advanced features for enterprise integrations.

Ads API (Carrot Ads)

The Carrot Ads API allows retailers and publishers to display sponsored product ads, track engagement, and manage advertising campaigns within their applications.

1.2 Server Environments

Environment Base URL Purpose
Development https://connect.dev.instacart.tools Testing and development
Production https://connect.instacart.com Live production environment

2. Authentication and Security

2.1 Developer Platform API Authentication

The Developer Platform API uses API key authentication with Bearer tokens. To authenticate requests, include the API key in the Authorization header: 

Authorization: Bearer <API-key>

2.2 Connect APIs Authentication

Connect APIs use OAuth 2.0 for authentication with two main grant types:

Client Credentials Grant

Used for backend implementations where your server calls Instacart directly. Provides access to backend endpoints that require user_id as a parameter. 

POST /v2/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_id=your_client_id
&client_secret=your_client_secret
&scope=api

User Access Token

Used for frontend implementations where the user ID is encoded within the token for client-side security.

POST /v2/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_id=your_client_id
&client_secret=your_client_secret
&scope=user:user_id

2.3 Request Headers

Header Required Description
Authorization Yes Bearer token for authentication
Content-Type Yes application/json
Accept Optional application/json
Accept-Language Optional en-US, en-CA, fr-CA

2.4 Rate Limiting

All APIs implement rate limiting to prevent abuse and ensure system stability. If you exceed the rate limit, you will receive a 429 Too Many Requests error. The system monitors request rates and may adjust limits based on usage patterns.

Warning: If you repeatedly receive 429 errors, contact your Instacart representative to discuss your integration and potential rate limit adjustments.

3. Developer Platform API

3.1 Overview

The Developer Platform API provides a streamlined way to integrate Instacart shopping capabilities into applications and websites. It's designed for developers who want to create shoppable recipes, shopping lists, or basic shopping experiences.

3.2 Getting Started

  1. Sign up: Request development access and create your account
  2. Create API key: Generate a development API key
  3. Start building: Follow tutorials and explore API reference
  4. Apply for affiliate account: Optional, for tracking conversions and payments
  5. Go live: Complete pre-launch checklist and create production API key

3.3 Request Structure

All requests use HTTPS and follow this URL structure:

https://connect.instacart.com/idp/v1/<endpoint>

3.4 Data Formats

The API supports various data types as defined in the OpenAPI Specification:

  • Integer data: All integer fields support int64 format unless otherwise specified
  • String data: UTF-8 encoding with no length limits unless specified
  • Response format: JSON with predictable, resource-oriented structure

4. Connect APIs

4.1 Overview

Connect APIs are designed for retailers who want to add comprehensive Instacart capabilities to their branded e-commerce sites. These REST-based APIs provide full-service shopping, delivery, pickup, and customer management functionality.

4.2 API Collections

Fulfillment API

Offers customers scheduling, full-service shopping, delivery, pickup, and last mile delivery options.

Recommendations API

Provides recommendations for replacement items and complementary products to enhance the shopping experience.

Sandbox API

Allows simulation of order status changes and callbacks for testing integration workflows.

Transaction API

Handles transaction reporting and affiliate tracking for revenue attribution.

4.3 Secure Communication

All Connect API communications use HTTPS for enhanced data privacy and security. The URL structure follows this pattern:

https://<instacart_domain>/v2/<endpoint>

4.4 Backward Compatibility

All API changes maintain backward compatibility. New fields are optional and can be ignored to maintain existing functionality. The deprecation policy ensures deprecated items remain supported for a minimum of six months.

5. Fulfillment API

5.1 Overview

The Fulfillment API combines the functionality of a Grocery API, Delivery API, and Pickup API into a comprehensive solution for e-commerce fulfillment. It supports multiple fulfillment options including delivery, pickup, and last mile delivery.

5.2 Core Endpoints

Store Management

POST /v2/fulfillment/stores/delivery POST /v2/fulfillment/stores/pickup POST /v2/fulfillment/stores/lastmile

These endpoints find stores offering specific fulfillment options based on customer location. Stores are returned sorted by distance, with eligibility flags for different service types.

User Management

POST /v2/fulfillment/users POST /v2/fulfillment/users/{user_id}/link GET /v2/fulfillment/users/{user_id}/link

User management endpoints create Connect user accounts, link Instacart accounts, and manage user preferences. The Connect user account is separate from both retailer customer accounts and Instacart accounts.

Service Options

POST /v2/fulfillment/service_options POST /v2/fulfillment/users/{user_id}/service_options

Service options endpoints retrieve available time slots for delivery or pickup, both for preview (before login) and reservation (during checkout).

Order Management

POST /v2/fulfillment/users/{user_id}/orders/delivery POST /v2/fulfillment/users/{user_id}/orders/pickup GET /v2/fulfillment/users/{user_id}/orders/{order_id} PUT /v2/fulfillment/users/{user_id}/orders/{order_id} DELETE /v2/fulfillment/users/{user_id}/orders/{order_id}

5.3 Store Discovery Implementation

The store discovery process allows customers to find nearby stores that offer their desired fulfillment method: 

curl --request POST \
  --url https://connect.instacart.com/v2/fulfillment/stores/delivery \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "find_by": {
      "latitude": 37.7749,
      "longitude": -122.4194
    }
  }'

The response includes store information with capability flags:

{
  "stores": [
    {
      "name": "Store Name",
      "location_code": "000-12345",
      "flags": {
        "alcohol": true,
        "pickup": true,
        "pickup_only": false,
        "long_distance_delivery": false
      }
    }
  ],
  "is_partial": false
}

5.4 User Account Creation

Creating a Connect user account is the first step in the fulfillment process:

curl --request POST \
  --url https://connect.instacart.com/v2/fulfillment/users \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "user_id": "unique_user_identifier",
    "first_name": "John",
    "last_name": "Doe",
    "phone_number": "5555551234",
    "locale": "en-US"
  }'

5.5 Order Creation

Creating orders requires a reserved service option and properly formatted item data:

curl --request POST \
  --url 'https://connect.instacart.com/v2/fulfillment/users/{user_id}/orders/delivery' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "order_id": "retailer_order_123",
    "service_option_hold_id": 12345,
    "initial_tip_cents": 500,
    "location_code": "000-12345",
    "address": {
      "address_line_1": "123 Main Street",
      "address_line_2": "Apt 4B",
      "postal_code": "12345"
    },
    "items": [
      {
        "line_num": "1",
        "count": 2,
        "item": {
          "upc": "123456789012"
        }
      }
    ]
  }'

5.6 Product Quantity Types

Items in orders require either a count or weight depending on the product's catalog configuration:

  • Count-based items: Discrete products like bottles, packages, or individual items
  • Weight-based items: Products sold by weight like deli meats, produce, or bulk items

5.7 Compliance Features

Alcohol Compliance

Orders containing alcohol require age verification and compliance with local laws. The customer's birthday must be included in the order, and deliveries are restricted to approved time windows and locations.

EBT Payment Support

The API supports EBT (Electronic Benefit Transfer) payments for eligible food items. Set the paid_with_ebt flag to true when creating orders paid with EBT cards.

6. Recommendations API

6.1 Overview

The Recommendations API provides intelligent product recommendations to enhance the shopping experience. It offers two types of recommendations: replacement items for out-of-stock products and complementary items to increase basket size.

6.2 Implementation Types

Backend Implementation

For backend implementations, use client credentials access tokens with user_id as a parameter:

POST /v2/recommendations/users/{user_id}/replacement_items POST /v2/recommendations/users/{user_id}/complementary_items

Frontend Implementation

For frontend implementations, use user access tokens with encoded user_id:

POST /v2/recommendations/replacement_items POST /v2/recommendations/complementary_items

6.3 Replacement Items

Replacement item recommendations help customers find suitable alternatives when their preferred products are unavailable: 

curl --request POST \
  --url 'https://connect.instacart.com/v2/recommendations/users/{user_id}/replacement_items' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "items": [
      {
        "upc": "123456789012"
      }
    ]
  }'

6.4 Complementary Items

Complementary item recommendations suggest additional products that pair well with items in the customer's cart: 

curl --request POST \
  --url 'https://connect.instacart.com/v2/recommendations/users/{user_id}/complementary_items' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "items": [
      {
        "upc": "123456789012"
      }
    ]
  }'

7. Ads API (Carrot Ads)

7.1 Overview

The Carrot Ads API enables retailers and publishers to display sponsored product ads and track engagement. It provides comprehensive advertising functionality including sponsored products, display ads, and brand pages.

7.2 Core Endpoints

Endpoint Description
/v2/ian/sp Retrieves sponsored product ad content
/v2/ian/dp Retrieves display placements and ads
/v2/ian/bp Retrieves brand pages curated by advertisers
/v2/ian/track Sends ad-related events and tracking data
/v2/ian/order/log Ingests order data for attribution

7.3 Sponsored Products

Sponsored products are ads that appear within search results and product listings:

curl --request GET \
  --url 'https://connect.instacart.com/v2/ian/sp' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <token>' \
  --data '{
    "query": "organic apples",
    "limit": 10
  }'

7.4 Event Tracking

Tracking ad events is crucial for attribution and campaign optimization:

curl --request POST \
  --url 'https://connect.instacart.com/v2/ian/track' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "event_type": "click",
    "ad_id": "ad_123456",
    "user_id": "user_789",
    "timestamp": "2024-01-01T12:00:00Z"
  }'

7.5 Ad Event Types

  • Impression: Ad was displayed to user
  • Click: User clicked on the ad
  • Add to Cart: User added advertised product to cart
  • Purchase: User completed purchase of advertised product

8. Sandbox API

8.1 Overview

The Sandbox API allows developers to simulate order lifecycle events for testing purposes. It provides endpoints to create test scenarios without affecting real orders or triggering actual fulfillment processes.

8.2 Core Endpoints

POST /v2/sandbox/shoppers POST /v2/sandbox/orders/{order_id}/callbacks PUT /v2/sandbox/orders/{order_id}/status

8.3 Simulating Order Lifecycle

The Sandbox API can simulate various order states and transitions:

  1. Order Created: Initial order state after successful creation
  2. Shopper Assigned: A shopper has been assigned to the order
  3. Shopping Started: Shopper has begun shopping for the order
  4. Order Fulfilled: Shopping is complete and order is ready for delivery
  5. Order Delivered: Order has been delivered to customer

8.4 Testing Callbacks

Simulate webhook callbacks to test your integration's handling of order status changes:

curl --request POST \
  --url 'https://connect.instacart.com/v2/sandbox/orders/{order_id}/callbacks' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "event_type": "order_status_changed",
    "new_status": "delivered"
  }'

9. Webhooks and Event Callbacks

9.1 Overview

Webhooks enable real-time notifications about order status changes and other events. They provide a way for your application to receive immediate updates without polling the API.

9.2 Webhook Configuration

Webhooks are configured through the Instacart Developer Dashboard. You can set up different webhook endpoints for development and production environments.

9.3 Event Types

Event Type Description
order_created New order has been created
order_updated Order details have been modified
order_cancelled Order has been cancelled
shopper_assigned Shopper has been assigned to order
shopping_started Shopper has started shopping
order_fulfilled Order has been fulfilled and ready for delivery
order_delivered Order has been delivered to customer

9.4 Webhook Payload Structure

{
  "event_type": "order_status_changed",
  "event_id": "evt_123456789",
  "timestamp": "2024-01-01T12:00:00Z",
  "data": {
    "order_id": "order_123456",
    "user_id": "user_789",
    "old_status": "shopping",
    "new_status": "fulfilled",
    "fulfillment_details": {
      "store_location": "000-12345",
      "estimated_delivery": "2024-01-01T14:00:00Z"
    }
  }
}

9.5 Webhook Security

Webhook payloads are signed with HMAC-SHA256 to ensure authenticity. Verify the signature using your webhook secret: 

X-Instacart-Signature: sha256=<signature>

10. Error Handling and Status Codes

10.1 HTTP Status Codes

Status Code Description
200 Success
201 Created
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
423 Locked
429 Too Many Requests
500 Internal Server Error

10.2 Error Response Format

API errors return structured JSON responses with detailed error information:

{
  "error": {
    "message": "User Not Found",
    "error_code": 1001
  },
  "meta": {
    "key": "user_id"
  }
}

10.3 Common Error Scenarios

Authentication Errors

  • 401 Unauthorized: Invalid or expired access token
  • 403 Forbidden: Insufficient permissions for requested resource

Validation Errors

  • 400 Bad Request: Invalid request parameters or format
  • 422 Unprocessable Entity: Valid format but business logic validation failed

Rate Limiting

  • 429 Too Many Requests: Rate limit exceeded, retry after delay

11. Best Practices and Implementation Guidelines

11.1 Authentication Best Practices

  • Secure Token Storage: Store access tokens securely and never expose them in client-side code
  • Token Refresh: Implement automatic token refresh logic for long-running applications
  • Environment Separation: Use separate credentials for development and production

11.2 API Integration Best Practices

  • Idempotency: Use unique order IDs and implement retry logic for failed requests
  • Error Handling: Implement comprehensive error handling for all API responses
  • Logging: Log all API interactions for debugging and monitoring
  • Timeout Handling: Set appropriate timeout values for API requests

11.3 Performance Optimization

  • Caching: Cache store lists and service options to reduce API calls
  • Batch Operations: Use batch endpoints when available to reduce request volume
  • Pagination: Implement proper pagination for large result sets

11.4 User Experience Considerations

  • Real-time Updates: Use webhooks for real-time order status updates
  • Graceful Degradation: Handle API failures gracefully with fallback options
  • Loading States: Provide clear loading indicators during API calls
  • Error Messages: Display user-friendly error messages based on API responses

11.5 Security Considerations

  • HTTPS Only: Always use HTTPS for all API communications
  • Input Validation: Validate all user inputs before sending to API
  • Data Minimization: Only collect and transmit necessary customer data
  • PCI Compliance: Follow PCI DSS requirements for payment-related data

11.6 Testing and Quality Assurance

  • Sandbox Testing: Use the Sandbox API for thorough testing before production
  • Edge Case Testing: Test error scenarios and edge cases
  • Load Testing: Perform load testing to ensure scalability
  • Integration Testing: Test the complete order lifecycle end-to-end
Note: This comprehensive guide covers the essential aspects of Instacart's API ecosystem. For the most current information and detailed endpoint specifications, refer to the official Instacart API documentation at https://docs.instacart.com.
