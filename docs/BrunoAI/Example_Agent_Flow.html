Example Agent Flow

Fulfilling a User Task with Bruno AI V3.0 Agent System

To illustrate how the V3.0 agent system handles a user query like "I want Caribbean meals for 4 people on a $200 budget," I'll break it down step-by-step. This scenario emphasizes the app's goal of collaborative assistance: Bruno AI acts as a partner, querying user wants (e.g., specific dishes or prep preferences) and adapting iteratively without imposing unrelated suggestions. The system uses ADK for orchestration (e.g., ParallelAgent for concurrent tasks), A2A for peer collaboration (e.g., JSON-RPC messages between agents), and MCP for structured tool access (e.g., Instacart API calls). No central master agent means distributed, efficient flows.

The process focuses on user empowerment: Agents confirm preferences, generate practical outputs (shopping lists, inventory checks, prep ideas), and refine via feedback. Estimated metrics: Response time <1.5s; Token efficiency via optimizer (20-30% savings); User alignment 95%+ through iterations.

Step 1: Query Intake and Initial Orchestration (Gateway Workflow Agent)

How it Starts: The user's query enters via the mobile app's conversational UI. The Gateway Workflow Agent (an ADK ParallelAgent) analyzes the intent: Caribbean-themed meal prep for 4, under $200. It spawns parallel tasks to avoid delays, routing to relevant agents based on A2A Agent Cards (metadata describing skills like "recipe-search" or "budget-optimization").

Collaboration Trigger: Gateway broadcasts the query context (e.g., budget, party size, cuisine) via A2A messages, enabling peers to self-coordinate.

User Focus: Bruno responds initially: "Got it—Caribbean meals for 4 on $200. What specific wants do you have, like favorite dishes or using pantry items?"

Step 2: Parallel Task Execution (Core Agents Activate)

The Gateway uses ADK's ParallelAgent to run concurrent subtasks, ensuring quick aggregation. Agents communicate via A2A for real-time sharing (e.g., SSE streaming for updates).

Recipe Chef Agent (Lead for Meal Ideas)

Role in Task: Generates Caribbean recipe suggestions (e.g., jerk chicken, rice and peas) scaled for 4, based on user wants. Uses MCP tools for recipe databases (structured queries like "fetch Caribbean recipes under 1-hour prep").

Collaboration: Sends A2A message to Budget Analyst ("Validate costs for these ingredients?") and Pantry Manager ("Check for available staples like rice?"). Adapts if user specifies (e.g., "Make it vegetarian").

Output: A list of 3-5 meal ideas with prep steps, sent back to Gateway for aggregation.

Budget Analyst Agent (Cost Validation)

Role in Task: Forecasts total spend ($200 cap), simulating costs for recipes. Uses MCP for pricing tools (e.g., aggregate estimates).

Collaboration: Receives A2A from Recipe Chef, queries Instacart Agent via peer link ("Current prices for jerk seasoning?"). Suggests adjustments like "Swap for cheaper alternatives to fit $200."

Output: Breakdown (e.g., "$45 per meal, total $180—room for extras?"), ensuring user-driven (no unsolicited cuts).

Instacart Integration Agent (Shopping Fulfillment)

Role in Task: Builds a shopping list from recipes, checking real-time prices/availability within $200. Uses MCP for Instacart API (e.g., structured calls: "Search items: plantains, quantity:4").

Collaboration: A2A with Pantry Manager ("Avoid duplicates from inventory?") and Budget Analyst ("Optimize for deals?"). Generates deep links for one-click ordering.

Output: Curated list (e.g., "Items totaling $175 from local stores—ready to order?").

Pantry Manager Agent (Inventory Check)

Role in Task: Scans user pantry (via app data) for Caribbean-compatible items (e.g., spices, rice), suggesting integrations to reduce shopping needs.

Collaboration: A2A peers with Instacart ("Replenish low coconut milk?") and Recipe Chef ("Adapt recipes to use existing onions?").

Output: Report like "You have rice—saves $5; want to prioritize other staples?"

Step 3: Aggregation and Iteration (Reflection & Feedback Agent)

Role in Task: The Gateway transitions to a SequentialAgent flow for review. This agent aggregates outputs (e.g., combined meal plan + list under $200) and prompts user feedback: "Here's a Caribbean plan for 4: Jerk tofu, etc., totaling $180. Does this match your wants, or adjust for spice level?"

Collaboration: If refinements needed (e.g., user says "Add more seafood"), it loops via ADK LoopAgent, re-querying peers via A2A.

Token Management: Optimizer compresses shared contexts (e.g., summarize recipe lists) to keep under limits.

Step 4: Final Delivery and Completion

User-Centric Close: Bruno presents the plan via app (e.g., "Based on your inputs, here's your customized Caribbean setup for 4—shopping link ready. Anything else?").

Task Fulfillment Metrics: Completes in ~2-3 turns; 99% reliability via A2A retries and ADK circuit breakers.

This flow demonstrates V3's strength: Distributed agents collaborate seamlessly (A2A/MCP) while staying adaptive and non-prescriptive, fully aligning with the app's collaborative goal. If the user provides more details (e.g., pantry contents), agents refine further.
