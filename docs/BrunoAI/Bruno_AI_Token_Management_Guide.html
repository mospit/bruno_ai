Comprehensive Token Management Guide for Bruno AI

This guide provides strategies for managing tokens in the Bruno AI V3.1 system, focusing on context compression, caching, and related techniques. Tailored to dependencies like FastA2A (for A2A protocol), PydanticAI (agent framework), Claude models (Sonnet 4 for complex, Haiku for efficient), Redis/Postgres (data layer), and Instacart API (tools), it aims to reduce costs (20-40% savings), latency (<1s for Haiku tasks), and overflows in multi-agent collaborations (e.g., sharing contexts for $200 Caribbean meals). Tokens are critical in Claude setups (e.g., Sonnet 4: 200K context window, but high per-token cost), so focus on efficiency without losing user-driven adaptability.

1. Token Challenges in Bruno AI

  • Dependencies Impact: Multi-agent A2A comms (JSON-RPC messages) inflate tokens via repeated contexts; Claude calls (e.g., Sonnet for reasoning) consume more than Haiku; Instacart tools add structured data.
  • Common Issues: Long histories in feedback loops (Reflection Agent); API responses bloating prompts.
  • Goals: Limit to 8K-16K per call; target 25% reduction via optimizations.

2. Context Compression Strategies

Compress prompts/contexts to fit Claude limits while preserving user wants (e.g., budget/cuisine).

LLM-Based Summarization

Use Haiku to summarize A2A histories before forwarding (e.g., condense pantry list to key items).

  • Implementation: In PydanticAI, add a pre-process hook: def compress_context(context): return haiku_client.summarize(context, "Retain user wants like budget $200"). Integrate in FastA2A Worker for async compression.
  • Example Code:
from anthropic import Client  # Claude API
from fasta2a import Worker

haiku_client = Client(model="claude-3.5-haiku")
class CompressedWorker(Worker):
    async def process(self, task):
        task.context = haiku_client.summarize(task.context, "Summarize keeping budget/cuisine wants")
        return await super().process(task)  # Proceed to Sonnet if needed
  • Benefits: 40-60% token reduction; preserves collaboration (e.g., summarize A2A from Recipe to Budget).

Truncation & Prioritization

Trim old messages, keeping recent user wants; use FastA2A context_id for selective recall.

  • Tip: In Redis, store compressed versions: redis.set('context:' + id, compressed_data).

3. Caching Mechanisms

Cache repetitive data (e.g., Instacart prices, user preferences) to avoid redundant Claude calls.

Redis for Context/Results

Use as FastA2A Storage for task persistence; cache A2A responses (e.g., pricing queries) with TTL (1hr for volatile data like prices).

  • Implementation: In FastA2A: storage=RedisStorage(redis_url='redis://localhost'). For PydanticAI agents: Check cache before Claude call.
  • Example Code:
import redis
from pydantic_ai import Agent

r = redis.Redis()
def cached_agent(agent):
    def wrapper(query):
        key = f"cache:{hash(query)}"
        if cached := r.get(key):
            return cached
        result = agent(query)
        r.set(key, result, ex=3600)  # 1hr TTL
        return result
pantry_agent = Agent('anthropic:claude-3.5-haiku', wrapper=cached_agent)
  • Benefits: 70-85% hit ratio (as in V2.0); reduces tokens for repeated tasks (e.g., budget checks in loops).

Postgres for Long-Term

Store user wants/history; query via MCP-like tools in PydanticAI.

  • Hybrid: Redis for hot caches, Postgres for cold (e.g., meal prep histories).

Claude-Specific

Cache summaries; use Haiku for cache hits validation.

4. Model Routing and Allocation

Route to Haiku for simple (e.g., inventory), Sonnet 4 for complex (e.g., feedback).

Dynamic Routing

In PydanticAI, classify queries (e.g., keyword match for "budget" → Sonnet).

  • Example: Custom router: if 'complex' in query: use_sonnet else use_haiku.
  • FastA2A Tie-In: Route in Worker based on task type.

Benefits: 30% cost savings (Haiku ~50% cheaper); faster for user queries.

5. Other Techniques

  • Prompt Engineering: Short, focused prompts (e.g., "Adapt to wants: $200 Caribbean" – limit to 1K tokens).
  • Batching: Group A2A messages in FastA2A Broker for bulk Claude calls.
  • Monitoring: Track via PydanticAI logs; custom tool for alerts (e.g., >10K tokens).
  • Error Handling: Fallback to Haiku on overflows; compress in retries.

Best Practices for Dependencies

  • FastA2A: Use Storage for token-efficient persistence; Broker for async batching in multi-agent.
  • PydanticAI/Claude: Set max_tokens in calls; compress via Haiku pre-step.
  • Redis/Postgres: TTLs prevent stale data; MCP tools for structured caching.
  • Instacart API: Cache responses (e.g., prices) to avoid repeated tool calls.
