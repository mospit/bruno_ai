ADK Agent Development Guide
Types & Patterns

1. Introduction to Agent Development Kit (ADK)

The Agent Development Kit (ADK) is a flexible and modular framework for developing and deploying AI agents. While optimized for Gemini and the Google ecosystem, ADK is model-agnostic, deployment-agnostic, and built for compatibility with other frameworks. ADK was designed to make agent development feel more like software development, enabling developers to create, deploy, and orchestrate agentic architectures ranging from simple tasks to complex workflows.

In ADK, an Agent is a self-contained execution unit designed to act autonomously to achieve specific goals. Agents can perform tasks, interact with users, utilize external tools, and coordinate with other agents. The foundation for all agents in ADK is the BaseAgent class, which serves as the fundamental blueprint for creating functional agents.

2. Core Agent Categories

ADK provides three distinct agent categories to build sophisticated applications, each serving different purposes and use cases.

2.1 LLM Agents (LlmAgent, Agent)

LLM Agents utilize Large Language Models as their core engine to understand natural language, reason, plan, generate responses, and dynamically decide how to proceed or which tools to use. These agents are ideal for flexible, language-centric tasks that require intelligent reasoning and dynamic decision-making.

Key Characteristics:

  • Intelligent Reasoning: Powered by LLMs for understanding and generating human-like responses
  • Dynamic Tool Selection: Can choose appropriate tools based on context and requirements
  • Flexible Behavior: Non-deterministic responses that adapt to different scenarios
  • Natural Language Processing: Excellent for conversational interfaces and text-based tasks

Implementation Example (Python):

from google.adk.agents import Agent

weather_agent = Agent(
    name="weather_time_agent",
    model="gemini-2.0-flash",
    description="Agent to answer questions about time and weather in a city",
    instruction="You are a helpful agent who can answer user questions about time and weather",
    tools=[get_weather, get_current_time]
)

Implementation Example (Java):

BaseAgent weatherAgent = LlmAgent.builder()

2.2 Workflow Agents

Workflow Agents are specialized components designed purely for orchestrating the execution flow of sub-agents in predefined, deterministic patterns. They control process flow without using an LLM for flow control itself, making them perfect for structured processes requiring predictable execution.

2.2.1 Sequential Agent

The SequentialAgent executes its sub-agents in the order they are specified in the list, passing the same InvocationContext sequentially to allow agents to easily pass results via shared state.

Implementation Example (Python):

from google.adk.agents import SequentialAgent, LlmAgent

step1 = LlmAgent(name="Step1_Fetch", output_key="data")
step2 = LlmAgent(name="Step2_Process", instruction="Process data from state key 'data'")

pipeline = SequentialAgent(name="MyPipeline", sub_agents=[step1, step2])

2.2.2 Parallel Agent

The ParallelAgent executes its sub-agents concurrently, dramatically speeding up workflows where tasks can be performed simultaneously. Events from sub-agents may be interleaved, and all parallel children access the same shared session state.

Implementation Example (Python):

from google.adk.agents import ParallelAgent, LlmAgent

fetch_weather = LlmAgent(name="WeatherFetcher", output_key="weather")
fetch_news = LlmAgent(name="NewsFetcher", output_key="news")

gatherer = ParallelAgent(name="InfoGatherer", sub_agents=[fetch_weather, fetch_news])

2.2.3 Loop Agent

The LoopAgent executes its sub-agents sequentially in a loop, repeatedly running a sequence of agents for a specified number of iterations or until a termination condition is met.

Implementation Example (Python):

from google.adk.agents import LoopAgent, LlmAgent, BaseAgent

process_step = LlmAgent(name="ProcessingStep")
check_condition = BaseAgent(name="Checker")

poller = LoopAgent(
    name="StatusPoller",
    max_iterations=10,
    sub_agents=[process_step, check_condition]
)

2.3 Custom Agents

Custom Agents are created by extending BaseAgent directly, allowing implementation of unique operational logic, specific control flows, or specialized integrations not covered by the standard types. These agents cater to highly tailored application requirements.

Key Features:

  • Ultimate Flexibility: Define arbitrary orchestration logic
  • Specialized Integrations: Connect to specific systems or protocols
  • Custom Control Flows: Implement unique decision-making patterns
  • Performance Optimization: Fine-tune for specific use cases

Implementation Example (Python):

from google.adk.agents import BaseAgent
from google.adk.events import Event
from typing import AsyncGenerator

class CustomProcessingAgent(BaseAgent):
    async def _run_async_impl(self, ctx: InvocationContext) -> AsyncGenerator[Event, None]:
        # Custom logic implementation
        data = ctx.session.state.get("input_data")
        processed_result = self.custom_processing_logic(data)

            author=self.name,
            content=types.Content(parts=[types.Part(text=processed_result)])

3. Multi-Agent Systems

As agentic applications grow in complexity, structuring them as multi-agent systems offers significant advantages including enhanced modularity, specialization, reusability, maintainability, and the ability to define structured control flows.

3.1 Agent Hierarchy

The foundation for structuring multi-agent systems is the parent-child relationship defined in BaseAgent. You create a tree structure by passing a list of agent instances to the sub_agents argument when initializing a parent agent.

Implementation Example (Python):

from google.adk.agents import LlmAgent, BaseAgent

# Define individual agents
greeter = LlmAgent(name="Greeter", model="gemini-2.0-flash")
task_doer = BaseAgent(name="TaskExecutor")

# Create parent agent with sub-agents
coordinator = LlmAgent(
    name="Coordinator",
    model="gemini-2.0-flash",
    description="I coordinate greetings and tasks",
    sub_agents=[greeter, task_doer]
)

3.2 Communication Mechanisms

Agents within a system communicate through several mechanisms:

3.2.1 Shared Session State

The most fundamental way for agents to communicate passively is through shared session state. One agent writes a value, and subsequent agents read it.

3.2.2 LLM-Driven Delegation

Leverages an LLmAgent's understanding to dynamically route tasks to other suitable agents within the hierarchy through transfer_to_agent function calls.

3.2.3 Explicit Invocation (AgentTool)

Allows an LLmAgent to treat another BaseAgent instance as a callable function or tool, providing synchronous, controlled invocation.

3.3 Common Multi-Agent Patterns

3.3.1 Coordinator/Dispatcher Pattern

A central LLmAgent manages several specialized sub-agents, routing incoming requests to the appropriate specialist agent.

Implementation Example:

billing_agent = LlmAgent(name="Billing", description="Handles billing inquiries")
support_agent = LlmAgent(name="Support", description="Handles technical support")

coordinator = LlmAgent(
    name="HelpDeskCoordinator",
    model="gemini-2.0-flash",
    instruction="Route user requests: Use Billing for payment issues, Support for technical problems",
    sub_agents=[billing_agent, support_agent]
)

3.3.2 Sequential Pipeline Pattern

A SequentialAgent contains sub-agents executed in a fixed order, implementing multi-step processes where output of one step feeds into the next.

3.3.3 Parallel Processing Pattern

A ParallelAgent executes multiple sub-agents concurrently to gather information or perform tasks simultaneously, improving overall system performance.

4. Tools and Implementation

Tools represent specific capabilities provided to AI agents, enabling them to perform actions and interact with the world beyond their core text generation abilities. ADK supports several types of tools.

4.1 Function Tools

User-defined code components tailored to specific application needs. These include standard functions/methods, agents-as-tools, and long-running function tools.

Implementation Example (Python):

def get_weather(city: str) -> dict:
    """Retrieves the current weather report for a specified city."""
    if city.lower() == "new york":
        return {
            "status": "success",
            "report": "The weather in New York is sunny with 25°C"
        }
    else:
        return {
            "status": "error",
            "error_message": f"Weather information for '{city}' is not available"
        }

4.2 Built-in Tools

Ready-to-use tools provided by the framework for common tasks, including Google Search, Code Execution, and Retrieval-Augmented Generation (RAG).

4.3 Third-Party Tools

Tools from external libraries such as LangChain Tools or CrewAI Tools, integrated seamlessly into ADK through wrapper interfaces.

4.4 Tool Context

For advanced scenarios, ADK provides ToolContext for accessing additional contextual information within tool functions:

  • state: Read and modify current session state
  • actions: Influence agent's subsequent actions
  • function_call_id: Unique identifier for tool invocation
  • auth_response: Authentication credentials if required

Implementation Example (Python):

from google.adk.tools import ToolContext

def update_user_preference(preference: str, value: str, tool_context: ToolContext):
    """Updates a user-specific preference."""
    user_prefs_key = "user:preferences"
    preferences = tool_context.state.get(user_prefs_key, {})
    preferences[preference] = value
    tool_context.state[user_prefs_key] = preferences
    return {"status": "success", "updated_preference": preference}

5. Development Best Practices

5.1 Agent Design Principles

  • Single Responsibility: Each agent should have a clear, well-defined purpose
  • Clear Instructions: Provide detailed, specific instructions for LLM agents
  • Proper Tool Documentation: Use descriptive function names and comprehensive docstrings
  • State Management: Use appropriate state prefixes (app:, user:, temp:)
  • Error Handling: Implement robust error handling and recovery mechanisms

5.2 Tool Development Guidelines

  • Function Naming: Use clear, descriptive names without spaces, periods, or dashes
  • Type Hints: Use strongly typed parameters to reduce model hallucinations
  • Documentation: Provide detailed descriptions with concrete examples
  • Return Values: Ensure JSON serializable outputs with status indicators
  • Context Usage: Leverage ToolContext for state management and flow control

5.3 Multi-Agent Architecture Guidelines

  • Hierarchy Design: Structure agent relationships logically
  • Communication Patterns: Choose appropriate communication mechanisms
  • Flow Control: Use workflow agents for deterministic processes
  • Dynamic Routing: Implement LLM-driven delegation for flexible routing
  • Performance Optimization: Use parallel processing where appropriate

6. Deployment Strategies

ADK agents can be deployed to various environments based on production readiness and flexibility requirements:

6.1 Agent Engine in Vertex AI

A fully managed auto-scaling service specifically designed for deploying, managing, and scaling AI agents built with ADK. Ideal for production workloads with minimal configuration requirements.

6.2 Cloud Run

A managed auto-scaling compute platform that enables running agents as container-based applications. Requires containerizing the agent application but provides excellent scalability and cost-effectiveness.

6.3 Google Kubernetes Engine (GKE)

A managed Kubernetes service providing more control over deployment configuration. Suitable for complex requirements, custom infrastructure needs, or running open-source models.

7. Performance and Evaluation

7.1 Agent Testing

ADK provides built-in testing capabilities through the web UI and API server commands:

  • Dev UI: Interactive testing with event inspection and tracing
  • API Server: Local FastAPI server for cURL testing
  • Terminal Testing: Command-line interaction for quick validation

7.2 Evaluation Framework

ADK supports systematic assessment of agent performance by evaluating both final response quality and step-by-step execution trajectory against predefined test cases. This includes comparing actual trajectories to expected ones to reveal errors and inefficiencies.

7.3 Observability and Monitoring

Integration with observability platforms like Arize AX provides comprehensive tracing, evaluation, and monitoring capabilities for ADK applications, enabling performance optimization and issue debugging.

8. Advanced Topics

8.1 Streaming and Real-time Interactions

ADK supports streaming capabilities for low-latency voice and video communication, enabling real-time agent interactions with users through multimodal interfaces.

8.2 Memory and Context Management

Advanced memory management techniques allow agents to maintain context across interactions and sessions, supporting long-running conversations and complex workflows.

8.3 Safety and Security

ADK includes built-in patterns and best practices for building safe and secure agents, including authentication management, input validation, and responsible AI implementation.

9. Conclusion

The Agent Development Kit provides a comprehensive framework for building sophisticated AI applications through modular agent design. By understanding the different agent types, communication patterns, and development best practices outlined in this guide, developers can create robust, scalable, and maintainable agentic systems that leverage the full potential of modern AI capabilities.

Whether building simple single-agent applications or complex multi-agent systems, ADK's flexible architecture and extensive tooling support enable developers to focus on creating value while the framework handles the underlying complexities of agent orchestration, communication, and deployment.
